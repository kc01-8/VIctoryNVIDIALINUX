# Asset policy (rule #1)

**Nothing from the game is ever stored in this repository.** Everything is
built on the user's machine from files the user supplies. The same applies
to other titles used for testing, and to any other proprietary material.

## Not allowed

In any form (files, string literals, fixtures, snapshots, docs):

* assets: models, textures, shaders, audio, video, text, archives;
* the executable or any part of it: data sections, strings, tables,
  resources, code beyond the signatures below;
* anything derived from those: converted assets, decompiled or
  disassembled code, shader dumps, extracted tables, screenshots.

## Allowed

* our own code that understands formats;
* build identities: BLAKE3 of an executable, CodeView GUID/age;
* per-build offsets of functions we hook, under names we choose;
* byte-pattern signatures that locate functions or data in the executable;
* small interoperability constants (magic numbers, enum values) we write;
* synthetic test data generated by our own code.

## No exceptions: the BCPack tables are supplied by the user

The constant tables of the BCPack format (entropy models, index rank
tables, control codes, per-format dictionaries) are not this project's
work, and the repository's licence does not cover them, so this fork does
not carry them: not in its files and not in its history (removed from
every commit on 2026-11-27). Upstream VIctory had shipped them as
`crates/victory-formats/src/bcpack-tables.bin`.

A BCPack stream cannot be decoded without exactly these tables, and they
cannot be derived. **Source them yourself**, from material you are
entitled to use, as one file: `bcpack-tables.bin`, 77,982 bytes, SHA-256
`1f1d4760419202bb5672f0c428ce51e456b5d08fbaec8f371d043fd94e01c36b`. Put it
beside `victory.exe`, or name it (or a folder that holds it) with
`VICTORY_BCPACK_TABLES`. Without it the title's BCPack-packed reads fail
and their textures stay empty. The file name is ignored by git here, and
the asset-policy check refuses it.

## Run logs

Logs of test and play runs are **not** published in this fork, scrubbed or
not: they record what a title did. Keep them outside the checkout (the run
scripts write under `~/.cache/victory`). `diagnostics/` is git-ignored, and
`xtask/src/policy.rs` refuses anything under it. Shader and pipeline hashes
may still be quoted in commit messages and docs.

## Where data lives

Outside the repository, configured in `victory.toml`: `game_dir` (the
user's dump), `test_titles`, and `cache_dir` for everything derived
(default `%LOCALAPPDATA%\victory\cache`).

Under Wine/Proton, vkd3d-proton and DXVK write shader caches
(`vkd3d-proton.cache`, `*.dxvk-cache`) into the current directory. They are
derived data and `.gitignore` covers them; to keep them out of the checkout
entirely, run from elsewhere or point `VKD3D_SHADER_CACHE_PATH` /
`DXVK_STATE_CACHE_PATH` at a directory outside the repository.
`scripts/victory-proton.sh` sets both paths to directories under the XDG
cache home by default.

## Enforcement

1. `.gitignore` keeps common data types out of `git status`.
2. `cargo xtask policy` (run by the pre-commit hook; install with
   `cargo xtask install-hooks`) is an allowlist: files must have an allowed
   type, be under 1 MiB, contain no binary data or known binary
   signatures, and hold no long hex/base64 runs. `.env` is allowed only
   for run profiles directly under `profiles/` (switch lines for
   `scripts/kc-run.sh`). Exceptions need an entry with a reason in
   `xtask/src/policy.rs`.
3. At runtime, everything that writes derived data calls
   `victory_core::ensure_outside_repo`.
4. Tests that need real files take their paths from environment variables
   and skip when unset. They assert on properties, never on snapshots.

## If something slips through

A follow-up commit is not enough. Rewrite history
(`git filter-repo --path <file> --invert-paths`), force-push, and have
everyone re-clone.
